## Notes

### Exceptions and `try-catch`

We discussed why exceptions need to be handled properly, especially when working with things such as external APIs. An API can fail or return an error, so we should not simply print the error in the console. Instead, we can use a `try-catch` block to handle the error and log it properly.

The `try` block contains the code that might fail, while the `catch` block handles the exception if something goes wrong. This makes the application more reliable and helps us understand errors when debugging.

---

### Generics in Java

We also discussed **Generics** in Java. Generics allow us to specify the type of data that a class, method, or collection will work with. They are written using angle brackets such as `<T>`.

This is useful because the same code can be reused for different data types while still maintaining type safety.

---

### Collections and Views

We discussed some of the common collections in Java, such as:

* `List`
* `LinkedList`
* `Queue`
* `Set`
* `HashMap`

These collections are useful for storing and managing groups of data depending on how we want to access or organize it.

We also discussed **views**. A view can represent a part or representation of existing data without necessarily creating a completely separate copy. This is useful when we want to work with existing data in a different way while keeping a connection with the original data.

---

### Events and GUI

We discussed how **events are connected to GUI applications**. An event is generated when something happens, such as a mouse click, key press, or window action.

The GUI receives these events and the appropriate listener or event handler responds to them. We also discussed the **Event Dispatch Thread (EDT)**, which is responsible for processing events and handling updates in Swing applications.

This helped me understand that GUI applications are not just about displaying components. They also need to continuously respond to user actions.

---

### Event Hierarchy

We discussed the **event hierarchy** and how different types of events are organized. Events can represent different actions such as mouse events, keyboard events, window events, and action events.

The event is generated by a source, such as a button or another GUI component, and is then handled by the appropriate listener.

Understanding this hierarchy helps in choosing the correct event and listener when developing a GUI application.

---

### Sliders

We discussed why sliders are useful in a GUI. Sliders are especially useful when the value is **continuous** and we want to experiment with different values before deciding what works best.

For example, instead of typing a value repeatedly, we can move a slider, observe the change, and choose the value that gives the desired result. This makes the interaction more intuitive for the user.

---

### Dialogue Boxes

We also discussed **dialogue boxes** and why they are used. A dialogue box can force the user's attention towards a particular task and prevent them from losing context.

They are useful when we need specific input from the user, such as a username, password, confirmation, or other short pieces of information.

Dialogue boxes can also be modal, meaning that the user has to respond to the dialogue before continuing with the rest of the application.

---

### Scrollbars

We discussed the purpose of **scrollbars**. They allow users to navigate through content that is larger than the available screen space without making the entire interface crowded.

However, the design of scrollbars is also important. If they are poorly designed or constantly shift around, they can become distracting and take attention away from the main interaction.

---

### Master-Detail Layout

We also discussed the **Master-Detail layout**, where one part of the interface shows a list of items and another part shows the details of the selected item.

For example, an email application can show a list of emails on one side and the contents of the selected email on the other side.

This layout is useful because it allows the user to move between different items while keeping the related information easily accessible.
