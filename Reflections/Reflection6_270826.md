### Topic 1: Maven Build Lifecycle

I was unable to attend this session, so I reviewed the topics covered in the lecture afterwards using the available class material.

The lecture covered the different phases of the Maven build lifecycle. Maven organizes the build process into a sequence of phases, where running a later phase also runs the earlier phases.

Some of the important commands discussed were `mvn compile`, `mvn test`, `mvn package` and `mvn install`. The `compile` phase compiles the main source code, while `test` also runs the tests. The `package` phase creates a package such as a JAR file, and `install` additionally places the package in the local Maven repository.

I also learned that `mvn build` is not a standard Maven lifecycle command. Instead, the appropriate command depends on what we want to achieve, such as compiling, testing or packaging the project.

### Topic 2: Java Source and Target Versions

The class also covered Java source and target versions. The source version determines which Java language features can be used in the source code, while the target version determines the version of Java bytecode generated by the compiler.

I learned that newer JVMs can generally run bytecode produced for older Java versions, but an older JVM cannot normally run bytecode created for a newer Java version. The `release` option can be used in Maven to configure the language features, bytecode version and available Java APIs together.

This topic helped me understand why specifying the Java version in a project is important when an application needs to run on different systems.

---

### Topic 3: Character Sets and Text Encoding

Another topic covered was character sets and text encoding. A character set defines the characters that can be represented, while an encoding defines how those characters are converted into bytes.

We discussed common encodings such as UTF-8, UTF-16, ISO-8859-1 and US-ASCII. UTF-8 is commonly used in modern projects because it supports Unicode and works well with many different languages.

I also learned that explicitly specifying the encoding in a Maven project can prevent text from being interpreted differently on different computers. Using the wrong encoding can result in corrupted or unreadable characters.

---

### Topic 4: Software Compatibility

The lecture discussed backward and forward compatibility. **Backward compatibility** means that a newer version of a system can continue to work with software or data created for an older version.

**Forward compatibility** means that an older system can handle information produced by a newer version, usually by ignoring features that it does not understand. Java bytecode is not forward compatible, which means that code compiled for a newer Java version cannot normally run on an older JVM.

Understanding compatibility is important because developers need to consider which versions of Java their applications are expected to support.

---

### Topic 5: JUnit and Software Testing

The final part of the material focused on JUnit and software testing. JUnit is a testing framework used in Java to create automated tests. It provides annotations such as `@Test` and assertions such as `assertEquals` to check whether the program behaves as expected.

We also covered the difference between unit testing and integration testing. Unit testing focuses on a small part of the program, such as a method or class, and usually keeps its dependencies isolated. Integration testing checks whether multiple components work correctly together.

Unit tests are generally faster and easier to diagnose, while integration tests can identify problems with things such as databases, data flow and communication between different components.
